## DEC-S028: The Routine emits a fleet-status digest — the read side of the SPEC hub; rolling issues are pinned by config number

**Decision:** The nightly sync Routine grows a **read-side projection** — a *fleet-status digest* (Step 4.5) — that reuses the enumeration Steps 1–2 already perform and emits one durable, rolling `fleet: status` issue carrying, per project: schema version, last-activity date, open-PR count, migration status, throughput (best-effort from `throughput.py --fleet`), and divergence/pattern flags, plus cheap V1 deltas (idle nights, migration-stuck days, convergence streak) diffed from the issue's own prior body. Both this digest and the existing `routine: last run` summary (Step 4) are now addressed by a **config-pinned issue number** (`status_issue:` / `last_run_issue:` in `routine-config.yaml`), edited in place — not found by title search.

**Why now — the convergence is the trigger.** The sync write-path has opened **0 PRs four nights running** (`routine: last run` #122→#125): the fleet has converged (the logic-class files are byte-identical across all sources; every hybrid hunk auto-skips). The enumeration engine still fires nightly, assembles a complete snapshot of the estate, and discards it into a one-night issue. The SPEC's north-star "cross-project status view / `@portfolio` / `/all-projects`" was filed "not actionable yet" *before* the sync converged — back when a portfolio view looked like it needed its own traversal machinery built from scratch. That machinery now exists, runs nightly, and produces nothing. The digest is a cheap projection over data already paid for (Steps 1–2 + one PR-count call per repo + optional throughput) — no new schedule, traversal, or agent calls.

**Pinned-number rolling issues fix a latent bug.** DEC-S010 intended *one* rolling `routine: last run` issue, body-replaced each run. It never rolled — a stateless nightly run can't reliably find its own prior artifact by title, so it created a new issue every night, accreting to **34 open issues** by 2026-06-21. A stable handle (issue number in config) stops the accretion by construction — the same mechanism the digest needs anyway. The Routine performs a one-time close of the stale `routine: last run` issues once the pinned number is set. Bootstrap: the issues are created once (by hand or by the create-once fallback, which logs the number to pin); the Routine never edits its own config (Step 5 — config edits go through PRs).

**Separate read pass, never fused into `@sync-config`.** `@sync-config`'s job is diff classification; status aggregation is a different concern with a different output shape. The digest is a new Routine step that runs after sync and touches no agent. Naming this explicitly so a future reader doesn't "optimize" the digest into the classifier and reintroduce the coupling DEC-S017 warned against in the doc-review context.

**V1 / V2 split.** V1 (this DEC) is a stateless snapshot that computes deltas by diffing against its own prior issue body — no new storage. V2 (deferred) backs it with an Anthropic-hosted persistent stateful agent so cross-run trends become first-class rather than body-diffed; V1 deliberately needs none of that substrate.

**Throughput is best-effort.** `throughput.py` shells out to `gh`, but the Routine session uses the MCP github tools — if `gh` isn't on the runner, the throughput field is marked `n/a (gh unavailable)` and the rest of the digest still renders. A `--fleet` JSON mode was added to `throughput.py` for clean per-repo ingest. The digest is read-only — it never merges, pushes, or branches — and stays cheap (~one PR-count call per repo); if it ever spawns an agent the design has drifted.

**What changes:** `dev/claude/routines/nightly-sync.md` (new Step 4.5; Step 4 rewritten to pinned-number addressing + one-time stale close; Step 0 field list); `.claude/routine-config.yaml` (`status_issue:` / `last_run_issue:` / `digest:`); `dev/claude/scripts/throughput.py` (`--fleet` JSON mode + self-test coverage); `docs/SPEC.md` Future Direction marked partially actionable. The Routine prompt must also be re-pasted into the Routine config on claude.ai (the standing manual drift step — the Routine executes from claude.ai storage, not this file). Origin proposal: PR #127 (`docs/SPECS/2026-06-21-tiller-fleet-status-digest.md`).

**Schema:** additive config + a logic-class prompt change; no cross-file contract `/pull-seeds` enforces is touched, so `seeds-version` is unchanged (Eric's call, recorded here as no-bump, consistent with DEC-S023–S027). Rides the nightly Routine to downstream projects — though the digest itself only runs on the seeds-side Routine.
